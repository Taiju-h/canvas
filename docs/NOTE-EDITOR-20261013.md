# Kaeru ノート編集・オフライン対応（2026-10-13）

## 作業範囲

機能本体はWeb版。Ranは使用・実行しない。Webを読み込むためのAPK自体に修正が必要な場合のみ、APKの修正・ビルドも対象とする。継続指示はルートの `AGENTS.md` を参照。今回の変更はWeb側で完結し、APKの変更はない。

## 接続が必要な操作と保存の条件

- 初回のアプリ読み込み、端末に一度も取得していないノート／添付の取得、他端末との同期・共有、OpenAI APIの解析／文字起こしには通信が必要。通常の編集・保存・整理・書き出しを通信待ちで止めない。
- ブラウザの保存容量・データ消去の制約は残る。保存失敗を成功と表示せず、エラーを通知する。ローカル履歴は端末内の世代管理であり、別端末へのバックアップではない。
- 別ノート参照の保存時更新は、この端末に取得済みのノートが対象。未取得の参照元は `#REF!` と表示する。事前準備を行ってからオフラインへ移る。
- 自動段組みは最大200行まで。セルより大きい分割不能な画像・表は文章のようには分割しない。通常表の固定高と同じく、元データは保持する。
- PNGは現在の作業画面、DOCXは文章・表・本文画像の書き出し。キャンバスの全オブジェクトや手書き効果、ルビ組版の完全なWord再現ではない。ルビはWordでは括弧付きの読みとして出力する。

## AIのサーバー設定

APIキーはPHPサーバーの環境変数 `KAERUNOTE_OPENAI_API_KEY` にのみ設定する。クライアントやリポジトリに保存しない。必要なら `KAERUNOTE_AI_MODEL`、`KAERUNOTE_TRANSCRIBE_MODEL` でモデルを指定する。PHP cURL拡張が必要。

送信前に対象を画面で確認する。関連ノート解析では候補のタイトル・分類・本文抜粋も送る。APIには `store: false` を指定し、返された関連IDは所有者の候補一覧に限定する。API利用料金は契約に従う。実API接続はキーを設定した環境で確認する。

## 検証

- `npm run build`：TypeScript確認・本番Webビルド。
- `npm test`：JEXの本文・添付読み込みと不正アーカイブ拒否。
- `npm run test:offline`：PlaywrightによるWeb操作検証。PlaywrightとChromiumが必要。`CHROMIUM_EXECUTABLE`で既存Chromiumを指定できる。
- ブラウザ検証ではAPIをモックし、ブラウザの通信を切ってページを再読み込みする。書式、チェックの付け外し、リスト、表、段組み、ルビ、自己／別ノート参照、オフラインカテゴリ・添付・再読み込み・JEX取り込み、DOCX、レイアウト所属、新規メモの再同期中の追記保持を確認する。

本番へのデプロイや実APIへのデータ送信は、この変更の検証には含めない。
