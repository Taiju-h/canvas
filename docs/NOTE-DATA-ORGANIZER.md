# 自分のデータの取り出しとページ・フォルダ整理

左メニューの「ページ・フォルダを整理」、または設定の同名ボタンで整理ページを開く。直接開く場合は `/?view=organize`。ノートを開くと整理ページから編集画面へ戻る。

## 実際の保存先

| データ | サーバー | 端末内 |
| --- | --- | --- |
| ノート本文、編集レイヤー、分類、元の取り込み情報 | MySQL `canvas_documents.content_json`。所有者IDで取得を制限 | IndexedDB `canvas-offline-v1` の `documents`。アカウント別に一覧を絞り込む |
| 空フォルダを含むフォルダ定義 | MySQL `canvas_note_workspace.categories_json` | `kaerunote-workspace-offline-v2:<account>` に定義、未同期操作、共通基準、競合差分 |
| JEX等の添付原本 | `/var/www/canvas.uzero.style/var/attachments/<document_id>/<file_id>.bin` と名前・MIME等のJSON。公開ディレクトリ外 | IndexedDBの `images` に取得済み／未送信のBlob |
| Canvasにアップロードした画像 | MySQL `canvas_images.image_blob` とMIME | 同じIndexedDBの `images` |
| 編集履歴 | 現在の文書とは別にサーバー側の履歴管理を新設しない | IndexedDB `revisions`、最大25世代 |

「すべてのノートと添付を端末に保存」はオフライン用の内部保存であり、ダウンロードフォルダへファイルを作る操作ではない。ダウンロードするには添付の保存ボタン、本文の添付リンク、または整理ページの「データを取り出す」を使う。認証の利用者が異なると、その利用者のデータは表示・取得できない。

## ZIPで取り出す

「データを取り出す」には全ページと選択ページのZIP保存を置く。全ページにはゴミ箱も含む。オンライン時は全ページの一覧を再取得し、ページごとに最新の取得済み内容／未同期の本文を優先する。未取得の原本は既存の認証付きAPIから取得する。書き出しだけで本文や分類を更新しない。

- ZIPの `index.html` から各ページを開ける。ページ内の `index.html` と `note.md` は取得した画像・添付を相対パスで参照し、通信なしで読む。
- `note.json` は元のページID、revision、本文、分類、取り込み情報、添付情報、Canvas／レイヤー／図形を保持する。所有者のセッション、CSRFトークン、共有トークンは書き出さない。
- `files/` は取得した画像・添付の元のバイト列。ZIPのCRCを付ける。圧縮・画像変換を行わない。
- `folders.json` は空フォルダを含む定義、`workspace.json` は端末内の未同期分類と競合、`manifest.json` は保存したページと原本の件数・所在。
- ファイルが未取得、取得失敗、サイズ不一致、容量上限の場合はエラーを表示してZIP保存を中止する。不完全なZIPを成功として渡さない。
- ZIP全体の上限は512MiB。超える場合はページを分けて選択書き出しする。オフラインでは取得済みのページ・原本だけを取り出せる。

HTMLは文章を読むための出力。Canvasの全オブジェクトの画面再現や、ZIPからの自動復元機能ではない。Canvasの編集情報はJSONに保存する。現在のデータを取り出すもので、端末内の全履歴世代は含めない。

## ページとフォルダを整理する

フォルダ一覧、本文を含む検索、子フォルダの切替、ゴミ箱の切替、ページの複数選択を用意する。選択したページの移動、タグ追加・解除、フォルダ追加・名前変更・移動・削除を行える。フォルダ削除では本文と添付を保持し、分類の移動先を選ぶ。

ページ単位の分類変更は `assign` 操作として既存の端末分類キューへ保存する。本文・図形・取り込み元の情報は変更しない。IndexedDBへの複数ページ保存は単一トランザクションで実行し、途中で容量不足等が起きたら全ページを取り消す。同じ分類の再指定で更新日時を変えない。

同期は既存の分類専用APIを使用し、最新revisionを検証する。他端末で同じページの移動等があれば差分を表示し、端末／サーバーの分類を選べる。未同期の本文は保持する。分類のサーバー保存前に本文保存から分類を上書きしない。

「整理用MD・分類JSONを書き出す」はChatGPTへ渡す既存の形式。本文を読んだ整理案を分類JSONで戻せる。元のID・revisionは維持し、変更後のrevisionが異なる場合は再書き出しを求める。MDの認証付きリンクは原本の代わりにならないので、原本の回収にはZIPを使う。実ユーザーの本文・画像・整理結果を公開リポジトリへコミットしない。

## 検証

`npm test` は分類の競合、選択ページだけの変更、再起動、ZIPのCRC・日本語パス・原本バイト列・容量／危険なパス拒否を確認する。`npm run build` は型確認とWebビルド。

`node tests/organizer-flow.cjs` は架空APIと実際のWeb画面で、原本ダウンロード、複数移動・タグ・フォルダ、無変更時の更新抑止、IndexedDBの途中失敗と再試行、未同期本文・ゴミ箱・原本を含むZIP、原本欠損時の失敗、スマホ幅、オフライン再起動と競合解決を確認する。既存の `workspace-flow.cjs` と `note-offline.cjs` もCIで実行する。

この変更はWeb側。配布済みAPK 0.4.4のファイル保存機能を使い、新APKの作成は不要。本番公開、利用者の実データ回収、利用者のAndroid実機確認はCIの架空データ検証と区別する。
