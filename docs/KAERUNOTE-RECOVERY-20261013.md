# KaeruNote 操作・同期・APK更新

## 操作

カテゴリを選ぶとサイドバー内の一覧を絞り込む。パンくず／親カテゴリボタンで戻れる。重ね表示の復旧コミット f95ded9658 は維持する。「子カテゴリを含める」を一覧に明示し、横断検索中はカテゴリ・タグの絞り込みが適用されないと表示する。

「＋ このカテゴリに新規ノート」は0件でも表示される。端末へ新規ノートを保存して本文へフォーカスする。通信を待たずに編集できる。自動閉鎖ONは既存ノートを開く／新規を作る操作の成功時に閉じる。OFFはスマホでも一覧を保持する。

Note／Canvasの「詳細」は基本リボンの末尾に置き、独立した追加領域を開閉する。状態は端末に保存される。Noteの追加文字書式・画像配置・表設定と、Canvasのブラシ・図形／画像・文字・グリッド・レイヤー設定を既存の編集処理へ接続する。画像はレイアウトレイヤー、手書きはキャンバスレイヤーという既存のデータ構造を維持する。

## 分類同期

`kaerunote-workspace-offline-v2:<account>` に未同期操作と、最初の操作前のカテゴリ／ノート分類を記録する。操作は先に端末へ保存する。分類キューがある間、本文のアップロードは保留するが、本文・添付の端末保存は続ける。

サーバーの最新一覧と変更前の分類を比較する。独立したカテゴリ追加、本文だけの更新、独立したタグ追加は統合する。影響するカテゴリ階層の同時変更、同じノートの異なるカテゴリ変更は差分を表示する。端末側／サーバー側の選択は表示された分類スナップショットにだけ有効。再取得時に分類が変われば再確認する。選択は未同期分類操作のバッチ全体に適用すると画面上でも明示する。

既存の metadata-only トランザクションを使用し、最新の workspace revision と各ノート revision を確認する。競合／通信失敗時はキューを残して再試行する。成功後もローカル本文・添付は置換せず分類だけ整合させ、本文保存を再開する。IndexedDBには実際の共通基準本文／タイトル／revisionを保持し、再起動後の三者比較に使う。基準のない旧キューは自動上書きせず選択を求める。

分類表示は保存済み／同期待ち／同期中／競合あり／同期完了を区別する。ブラウザの容量不足で端末保存できない場合は成功と扱わない。

## Android 0.4.2-web-shell（code 9）

Web機能の二重実装はしない。Actionsは最新のWebビルドをAPK assetsへ同梱する。短い本番コミットとActionsの完全SHAは同一版として比較する。

新版の更新は、全ファイルを別ディレクトリへ取得→端末保存確認→静的UI切替→起動したバンドルのコミット確認の順。取得中に本番のbuild-versionが変わった場合やファイル欠損では適用しない。ノートID・URLハッシュを保持する。更新確認が届くまで旧UIを残し、確認失敗／途中のプロセス終了では旧UIまたは同梱UIへ戻す。IndexedDB・Cookie・ユーザーデータは消去しない。日本語の変換中は更新を適用しない。

Releaseは既存の4つのANDROID署名secretを使用する。欠落時は失敗とし、別鍵を生成しない。version変更を含む同一リポジトリPR／mainでビルドし、署名をapksignerで検証する。配布にはRelease署名APKを使用する。Debug署名APKを既存Releaseへ上書きする手順やアンインストールによるデータ消去を案内しない。

- `npm test`：JEX、分類の三者比較、旧キュー、端末再読込、本文／分類の統合、短いコミット比較。
- `npm run build`：TypeScript／Webビルド。
- `node tests/category-overlay.cjs`：5階層、マウス／タッチ、80%重なり、400大カテゴリ／200子カテゴリ、スクロール・管理操作。
- `node tests/workspace-flow.cjs`：実際のビルド済みUI＋架空API。カテゴリ選択、一覧、新規、書式選択、Canvas詳細、オフライン再起動、本文保持、分類競合、スマホ幅で自動閉鎖OFF。ユーザーデータは使用しない。
- JDK17／Gradle9.1.0で `assembleDebug assembleRelease lintDebug`。署名の確認はRelease Actionsで別途行う。
- 本番は `/var/www/canvas.uzero.style` で正本のmainを取得し、既存 `bin/upgrade-hybrid-v2.sh` を実行。公開 `https://canvas.uzero.style/canvas/build-version.json` とGitコミットを照合する。
- Android実機では既存APKの版／署名を確認して上書きし、ログイン・ノート・添付保持、更新通知、更新失敗の旧画面、オフライン再起動、日本語入力を実測する。実機未接続では未確認と報告する。

## 追加改善：カテゴリ・レイヤープロパティ・縦スクロール

カテゴリ見出しに常時「追加」と「削除」を表示する。削除ダイアログでは対象とノートの移動先を指定する。対象と子カテゴリの分類を削除するが、ノート本文・添付は保持する。作成・移動・タグ化・削除は同じ端末保存／競合比較のキューで扱う。

各レイヤー名およびリボンの「プロパティ」から、名前・不透明度・表示・ロックを編集する。Canvas／レイアウトには画像・PDF読み込みと表示範囲PNG／配置JSON書き出し、ノートにはTXT／MD読み込みとTXT／MD／Word書き出しを置く。テキストはUTF-8として読み、既存本文末尾へ追加する。既存の本文を置換しない。画像読み込み中も最新本文を再取得して配置だけ追加する。

PDFはPDF.jsを端末内で実行し、ページを画像化して指定レイヤーへ配置し、PDF原本を添付として保持する。64MB／200ページまで。ページを1枚ずつ端末保存し、途中エラー時は保存済み枚数を表示する。暗号化PDFには対応していない。ワーカー、CMap、フォント、WASMを同じオフライン一覧へ含める。外部CDNや外部PDF変換サービスは使わない。明示的に指定した画像のレイヤーは再読込でも保持する。PDF.js: https://mozilla.github.io/pdf.js/ （MPL-2.0、同梱サポート素材のLICENSEも配布対象）。

PNGは選択レイヤーの表示範囲、配置JSONはノート内画像参照を含む配置情報であり、画像原本を内包するバックアップではない。全ノート・添付のバックアップは既存の運用を使用する。Wordは従来の文字・表・画像出力を利用し、画面全体の完全再現は行わない。

旧UIではノート本文とCanvasが別々のスクロール領域だった。今回、同じスクロール領域に、拡大縮小されるCanvas平面と拡大縮小されないノートを兄弟要素として配置する。縦スクロールは同じピクセル量で移動し、Canvasズームでノートの文字サイズ・表示幅は変わらない。

## APKより本番Webが古い場合

ビルド済みUIと `build-version.json` にGitコミット時刻 `commitTime` を同時に記録する。更新通知は異なるコミットかつ新しいコミット時刻の場合に限定する。時刻がない旧本番画面は更新候補にしない。Android側も取得済み／同梱UIより古い画面の適用を拒否する。本番デプロイが未実施でも、新APKが旧Webへ戻ることを防ぐ。同じAPKバージョンの再ビルドでも同梱コミットの変更を検出して古い静的UIを除去する。IndexedDB・Cookieは消去しない。
