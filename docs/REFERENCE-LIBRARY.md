# 画像・YouTube・リンク・メモの資料一覧

ヘッダーの「資料」、または左メニューの「資料：画像・YouTube・リンク」から開く。

- 「すべて」「よく使う」「画像」「YouTube」「リンク」「メモ」で切り替える。
- 名前・元のメモ本文・URL・フォルダ・タグを横断検索できる。フォルダとタグでも絞り込める。
- ☆は資料単位の固定。メモの固定は既存の `note.pinned`、画像・リンクの固定は同じノートJSONの `note.referencePins` に保持し、通常の競合検出付き保存・同期を使う。
- Joplin取り込み後の本文・文章ボックスにある画像とリンクも抽出する。本文に裸のURLが残った旧メモも対象。元の本文・添付・分類・取り込み元情報は書き換えない。
- YouTubeの通常・短縮・Shorts・埋め込み・ライブURLを区別する。動画の自動取得や外部メタデータ取得は行わない。
- 画像はプレビュー・原本保存・元メモを開く操作を用意する。「挿入」で編集中のノートの末尾へ追加する。別ノートの画像を挿入する際は、画像を挿入先の独立した添付として端末にコピーし、通常の添付同期へ渡す。
- 「資料を追加」では名前・URL・フォルダ・タグ・固定を指定してリンクを保存できる。複数の画像ファイルは原本を端末に保存して、それぞれ画像メモを作る。メモの編集や削除は元のメモ画面と既存のゴミ箱を使う。
- 資料一覧は所有するノートだけを対象とし、共有リンク画面には表示しない。個人の内容は公開Gitへ含めない。

## 起動時の端末保存

接続確認後、ノート一覧の取得が完了すると自動で全ノート・画像・添付を端末へ保存する。既に保存した同じrevisionの本文と原本は再取得しない。編集や取り込みの途中では処理をまとめ、再接続時は再確認する。保存・同期中の本文を古いダウンロード結果で上書きしない。利用者の切り替え・画面終了時にはダウンロードを中止する。

ヘッダーの「端末保存」から保存件数・進み具合・未取得件数・再試行を確認できる。全件取得と画面の保存が両方成功した場合だけ「端末保存済み／オフライン準備完了」を表示する。一覧の取得失敗や添付の欠損は全件成功として扱わず、同じ条件での無限自動再試行はしない。

Webの初回はHTTPSで一度開き、画面とデータの取得完了まで待つ必要がある。インストール済みのService Workerは `/` と `/canvas/` を保存済みの画面から起動し、サーバーやログイン画面の応答を待たない。認証・同期は起動後に既存の処理で行う。IndexedDB、Cookie、ノート原本は更新で削除しない。

YouTube再生・外部サイト・外部URLの画像は接続が必要。ブラウザデータを消去すると端末のコピーも消えるため、原本のファイル書き出しには既存のZIP保存を使う。HTTP等で画面の保存を利用できない環境でもノート・画像の自動取得は続け、画面保存だけが未完了であることを明示する。

## 検証

- `npm test`：既存の47件に加え、URL判定・固定のJSON保持・安定した画像参照・通信断時の画面返却・必須/任意ファイル・API非キャッシュを検証する。
- `npm run build`：TypeScriptと本番ビルド。
- ブラウザでは端末専用ノートから、URL抽出・固定・追加・分類・画像の原本表示・別ノートへの画像挿入・再読み込み後の保持を確認する。
- 確認用APIデータで、未開封のノートとその画像まで自動取得されることを確認する。
- HTTPのプレビューはService Workerの実機検証には使わない。Service Workerの通信断テストとブラウザの端末保存確認、HTTPS本番・利用者の実機確認は区別する。

新規DBテーブルやSQL変更、WebViewシェルの変更は不要。既存のWeb更新手順 `bin/upgrade-hybrid-v2.sh` を使い、公開 `build-version.json` のコミットとmainを照合して反映を確認する。
