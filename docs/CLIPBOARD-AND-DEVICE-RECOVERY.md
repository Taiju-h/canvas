# 貼り付けと端末データのDB保存

## 貼り付け後の操作

- レイアウトでCtrl/⌘+V：文章は編集可能な文章ブロック、画像は個別の画像オブジェクトになる。黒矢印で選択して移動できる。文字入力中の通常のコピー・貼り付けは維持する。
- CanvasでCtrl/⌘+V：貼り付け用の新規レイヤーを作る。文章はCanvasの画像になり、画像は原本を保持する。「レイヤー全体を移動」で、そのレイヤーの画像・線・元画像をまとめて動かす。投げ縄で囲んだ部分の移動とは別の操作。
- Canvasで範囲を選ばずコピーすると、編集中のレイヤーをコピーする。投げ縄の範囲があればその部分をコピーする。貼り付けると新しいレイヤーになり、元のレイヤーを保持する。
- Vは投げ縄の選択がある場合に選択範囲の移動、ない場合にレイヤー全体の移動。Undo/Redoはドラッグ1回を1操作として扱う。ロック・非表示のレイヤー、Note・他のレイアウトを変更しない。
- アプリ内の右クリックメニューからもコピー・切り取り・貼り付けできる。ブラウザーのクリップボード許可が拒否された場合は理由を表示し、切り取り元を消さない。文章・画像の取得可能な形式はブラウザー側のクリップボードAPIに依存する。

## PCだけにメモが見える場合

端末の一覧は、IndexedDBの保存分と接続先DBの一覧を合わせて表示する。PCに件数が見えていても、すべての本文・添付がDBへ保存済みとは限らない。別アカウントや期限切れの認証、未同期・権限エラーがある場合は、端末データを保持して集約する。

1. PC側の左メニュー「端末のメモをDBへ保存」を開く。
2. 端末の件数・接続中のDB件数・保存済み分・コピー候補のタイトルを確認する。本文と原本を先に検査し、未取得の画像・添付がある場合は書き込み前に停止する。
3. 保存先が別の利用者へ切り替わっていた場合は「保存先を再確認」を使う。編集中の内容を端末へ保存してから切り替える。旧保存先のデータも残る。
4. DBへの保存を実行する。未同期またはDBに存在しないローカルの版を新しいメモとしてコピーし、既存DBの内容を上書きしない。本文・Canvas・レイアウト・元の分類・元データ・画像・添付と、移したメモ同士の内部リンクを保持する。空フォルダも追加する。
5. 中断・通信失敗後は保存状況を再確認する。メモと原本のチェックポイントを使って再開し、同じ保存分を二重取り込みしない。送信完了した元のローカル分は退避範囲で保持し、未同期の旧版が繰り返し保存エラーを出さないようにする。内容・原本・ローカル履歴は削除しない。
6. 「保存したメモを開く」でコピー先を開く。その後、同じ保存先に登録したAndroid・PC・iPadで読む。別端末でのオフライン利用は、その端末へのダウンロード完了後に行う。

個人専用設定をまだ有効にしていない場合は、コピー後に `bin/personal-access.php setup` を行う。確認画面の「サーバー初期設定で同じ保存先を選ぶ場合」で表示したIDと、setupの一覧のIDを照合する。個人専用化自体はデータの移行を行わない。導入と端末登録は `PERSONAL-ACCESS.md` を参照する。

## 保護と検証

- アカウントを切り替えて同一IDの文書を読み直すとき、異なるローカル内容は退避してからキャッシュを更新する。元の画像・添付IDと文書IDの関係も保持する。
- DB保存中はこの画面の通常の自動同期を止め、進行中の保存を待つ。操作前の原本を検査し、確認後に変更されたメモは再確認を求める。
- コピー先は直前のsession APIで再確認する。クライアントの旧アカウントIDを、そのままサーバーの認証として使用しない。端末に所有者として保存したメモが対象で、共同編集者のキャッシュは含めない。
- 途中のコピーはpendingにし、原本の転送と本文の保存後に完了を記録する。中断前に完成したコピーや他の端末の新しい編集は上書きしない。分類の競合でも元の端末データを保持する。
- CIは実際のキーボード/右クリックの貼り付け、Canvas画像の画素、レイアウトの個別移動、原本付きレイヤー移動とUndoを確認する。合成データで別アカウントのキャッシュ保護、チャンク送信失敗と再開、重複防止、リンク・原本ハッシュ、未取得原本での事前停止、新しいモバイルブラウザーからのDB読み込みを確認する。

実際のPCのメモはこのコード変更だけで自動移行されない。本番への反映と、元の端末での確認・保存操作が必要。ネイティブ側の変更はないため、新しいAPKは作成せず、0.4.6のWeb更新として配信する。
