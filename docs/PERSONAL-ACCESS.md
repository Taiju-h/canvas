# 個人専用のKaeruNoteと登録端末

Android・PC・iPadを同じ本人の保存先につなぐ。アプリの配布ファイルや公開URLだけでは、ノート・画像・添付・AI APIを使えない。サーバー上の個人専用設定と、端末ごとの登録が必要。

## 本番の切り替え

本番サーバーで既存の更新を実行してから、所有者を選ぶ。GitHubへのマージやAPKのインストールだけでは本番の個人専用設定は有効にならない。

```sh
sudo bash /var/www/canvas.uzero.style/bin/upgrade-hybrid-v2.sh
sudo php /var/www/canvas.uzero.style/bin/personal-access.php setup
```

既存利用者の名前・メモ件数・IDが表示される。本人のデータを使っている行番号を入力する。自動で他の利用者のデータを統合したり、新しい空アカウントに切り替えたりしない。ノート・添付・JEX取り込み内容・端末の未同期編集は削除しない。

最初の登録コードがサーバーの端末画面に1回表示される。有効時間は60分、使えるのは1台だけ。コードを公開のIssueやチャットログに貼らない。PHP実行ユーザーがwww-data以外の場合は `sudo CANVAS_PHP_USER=<実行ユーザー> php .../personal-access.php setup` を使う。設定ファイルをPHPが読める既存の権限は保持する。

1. Androidは同じ署名の0.4.6 / versionCode 13を上書きインストールする。アンインストールして端末データを消さない。
2. アプリを開き、端末名とコードを入力する。初回登録はオンラインで行う。
3. PCやiPadを追加するときは、登録済み端末のヘッダー「自分の端末」→「別の自分の端末を追加する」でコードを発行する。
4. 追加するPC・iPadで https://canvas.uzero.style/canvas/ を開いて入力する。追加コードは15分・1台限り。PCやiPadでAPKをインストールする必要はない。
5. 登録済み端末は同じ所有者のデータを取得する。ダウンロード完了したメモ・原本はオフラインでも利用できる。外部のYouTubeやWebリンクの再生・表示には通常インターネットが必要。

JEXの本番取り込みは別の操作。個人専用設定はデータの取り込みやDBファイルの復元を自動実行しない。

## 制限と回復

- 未登録端末、従来の会員・訪問者セッション、保存済みvisitorToken、共有URLは個人用データへの認証として扱わない。個人用では共有リンクの発行も無効。
- Android 0.4.5以前はサーバー利用を拒否して上書き更新を案内する。User-Agentの版確認は更新案内用であり、認証はランダムな端末秘密で行う。
- 登録許可は端末ごとに365日。期限切れ・Cookie消去・ブラウザ変更・アプリ再インストール時は新しいコードで再登録する。登録・解除だけでは端末のメモを消さない。
- 「自分の端末」から不要な登録を解除できる。解除はサーバーの次の要求から有効。開いている新UIもフォーカス復帰・オンライン復帰・30秒ごとの確認で編集領域を隠し、未同期編集を端末に保持する。
- 通信エラーでは登録済みオフライン利用を維持する。サーバーから登録解除・未登録・設定エラーが明示された場合は、古いログイン情報へ戻らない。
- オフライン端末や旧版へ既に保存したデータの遠隔消去はしない。紛失端末にはOSの画面ロックや端末管理を併用する。端末秘密自体をコピーされた場合は登録を解除する。
- Androidの自動バックアップ・別端末への転送には登録情報を含めない。必要なノートのファイル保存は従来のZIP書き出しを使う。
- Androidは旧Service Workerの起動用HTMLを経由せず、APK同梱／明示更新した画面から起動する。上書き更新時に旧画面が登録画面を覆うことを防ぎ、Cookie・IndexedDB・未同期データは保持する。

全端末を失った場合もサーバー上でコードを再発行できる。個人用設定を解除する必要はない。

```sh
cd /var/www/canvas.uzero.style
sudo php bin/personal-access.php invite
sudo php bin/personal-access.php devices
sudo php bin/personal-access.php revoke <端末ID>
```

## 保存先とアクセス境界

- 既存の `CONF/canvas-db.ini` の `[private_access]` に `enabled = true` と既存 `owner_id` を保存する。既定は未設定。setupは既存設定の上書き・再初期化を拒否する。
- `var/private-access/state.json` と別ロックファイルは公開ディレクトリ外・PHP実行ユーザーだけが読み書きできる権限。DB・`var/attachments` と一緒にサーバーで保護してバックアップする。古い状態へ戻すと登録解除も巻き戻るので、復元時は端末一覧を確認する。
- 128 bitの登録コードはハッシュだけを保存する。1回限り・短時間有効・IP/全体の試行上限あり。同時利用もファイルロックと原子的置換で1件だけ成功する。
- 端末秘密は256 bit。サーバーはハッシュだけを保存し、ブラウザにはHTTPSのSecure / HttpOnly / SameSite=Strict Cookieを発行する。JavaScript・localStorage・APK・Gitに秘密や登録コードを恒久保存しない。
- session API以外の本文・一覧・添付・画像・分類・AI・管理APIをサーバーで一括確認する。文書アクセスは従来のowner_id照合を維持する。以前の共有用セッション許可も無視する。
- 状態ファイル欠損・不一致・読み書き失敗ではAPIを停止し、一般公開モードへ戻さない。初期設定や復旧にはサーバー管理権限が必要。
- 登録済みの状態ファイルがある場合、INIの個人専用セクションを消したり無効にしたりしても一般公開へ戻らない。復旧時は同じowner_idの個人専用設定を戻す。
- `CANVAS_CONFIG_FILE` / `CANVAS_PRIVATE_STATE_FILE` は隔離テスト・管理用のサーバー環境変数。HTTPパラメーターから保存先を変更できない。

## 検証

`npm test` に登録とオフライン判定の検証を含む。CI `Personal device access` は実際のPHP 8.3/MySQL 8を使い、本文・画像・添付・他の所有者へのアクセス、旧ログイン、共有許可、コードの同時利用・再利用、CSRF、Cookie属性、解除・期限切れ、設定破損、試行上限を検証する。`tests/private-devices.cjs` は合成データで登録、Android/iPad共通の保存先、オフライン編集・再同期、解除時の未同期データ保持を確認する。実際の本人のデータをCIや公開Gitへ含めない。

署名済みAPKのビルド・従来版との証明書一致、Android API 29/36での確認、本番の反映、利用者の実機での確認を別々に記録する。
